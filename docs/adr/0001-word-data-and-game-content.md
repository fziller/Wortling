# ADR 0001: Word Data and Game Content

## Status

Accepted

## Context

Wortling must work fully offline. Word games need enough input validation data to feel fair, but daily solutions should remain curated so puzzles are understandable and not dictionary-noise.

Some games, especially `Dazwischen`, also depend on stable alphabetic ordering. Doing large word-list sorting on screen open blocks the JavaScript thread, especially on Android/Hermes.

## Decision

- Word lists are generated at development/build time and checked into the mobile app.
- The app does not fetch gameplay word lists at runtime.
- Each game distinguishes curated target words from generated allowed guesses.
- Target words are manually curated per game.
- Allowed guesses are generated by scripts from DWDS and German POS Dictionary sources.
- Generated allowed guesses that are used for rank-based gameplay must be emitted in final sorted order.
- Runtime game code may build small lookup structures such as `Set` and `Map`, but must avoid large locale-aware sorts during screen open.
- Content versions must be bumped when word data or rank order changes in a way that affects daily selection or saved progress.

## Consequences

- Gameplay starts without network access.
- Word-data changes are explicit and reviewable in generated files.
- Agents and humans can improve import scripts later without changing game engines.
- App startup and game navigation stay responsive because heavy word processing happens before runtime.
